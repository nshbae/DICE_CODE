# DICE_CODE
A 3D puzzle game where players solve room-based challenges by interpreting clues and using dice rolls as answers.

# DICE CODE

> 주사위의 “눈”을 해석하는 규칙이 매 스테이지마다 달라지는 3D 퍼즐 미궁 게임

**DICE CODE**는 하나의 주사위와 주변 환경에 주어진 단서를 이용해 규칙을 추론하고, 정답을 순서대로 입력하며 진행하는 3D 퍼즐 게임입니다.

모든 스테이지는 동일한 **주사위 → 슬롯 → 정답 판정** 구조를 공유하지만,
스테이지가 진행될수록 “현재 주사위의 값이 무엇인가?”를 판단하는 규칙 자체가 변화합니다.

숫자와 방향뿐 아니라 **색상, 중력, 소리, 공간적 위치, 빛과 그림자**까지 주사위의 상태를 결정하는 정보로 활용됩니다.

> **플랫폼:** PC  
> **엔진:** Unity  
> **언어:** C#  
> **역할:** 1인 개발
> **Busan Indie Connect Festival 2024 선정작**

---

## 게임 플레이

기본적인 퍼즐 진행 방식은 모든 스테이지에서 동일합니다.

1. 주사위를 직접 굴립니다.
2. 주사위가 멈추면 현재 **중력 방향을 기준으로 유효한 면**이 결정됩니다.
3. 원하는 슬롯을 선택하여 현재 주사위의 값을 입력합니다.
4. 필요한 경우 입력된 주사위를 회전하거나 제거할 수 있습니다.
5. 모든 슬롯의 값이 정답과 일치하면 스테이지를 완료합니다.

이 공통 규칙을 유지하면서, 각 스테이지에서는 주사위의 값을 해석하는 방법을 새롭게 변경합니다.

---

## 퍼즐 구성

이하 내용은 게임의 핵심 매커니즘과 정답에 대한 설명을 포함하고 있습니다.

스포일러를 피하고 싶으신 분들은 게임을 먼저 플레이하길 권장합니다.

실제 게임의 모습을 보고 싶으면 영상을 참고해주세요.

[![DICE CODE Gameplay](https://img.youtube.com/vi/QO5rReQvYoU/maxresdefault.jpg)](https://www.youtube.com/watch?v=QO5rReQvYoU)


### Stage 1 — Dice Faces

가장 기본적인 주사위 방향과 윗면 판정을 학습하는 스테이지입니다.

`1, 2, 3, 4, 5, 6`으로 표시된 슬롯에 각각 대응하는 주사위 눈이 위를 향하도록 주사위를 굴리고 입력합니다.

이 스테이지를 통해 이후 모든 퍼즐의 기반이 되는 다음 조작을 학습합니다.

- 주사위 굴리기
- 윗면 판정
- 슬롯 입력
- 정답 판정

---

### Stage 2 — Rotation / π

정면의 원형 문양과 소수점을 단서로 **π = 3.14159**를 추론하는 퍼즐입니다.

이 스테이지의 주사위에는 일반적인 눈 대신 아라비아 숫자가 표시되어 있습니다.

입력된 슬롯을 다시 선택하면 슬롯 내부의 주사위를 **90° 회전**시킬 수 있으며,
이를 이용해 `6`을 `9`로 뒤집어 사용할 수 있습니다.

즉, 주사위 면의 값뿐 아니라 **면의 회전 방향까지 정답 상태의 일부**로 사용됩니다.

---

### Stage 3 — RGB / CMY

주사위의 각 면에는 별도의 문자나 숫자가 표시되지 않으며,
주사위를 굴린 결과에 따라 주사위의 색상이 변경됩니다.

각 결과는 RGB 색상 체계의 색과 연결됩니다.

- Red
- Green
- Blue
- Cyan
- Magenta
- Yellow

플레이어는 주변의 RGB 문양과 빛의 색 혼합 규칙을 이용하여
RGB와 CMY에 대응하는 색상 배열을 완성해야 합니다.

---

### Stage 4 — GRAVITY

주사위에는 다음 여섯 글자가 배치되어 있습니다.

`G / R / A / I / T / Y`

주사위의 결과에 따라 Unity의 **전역 중력 방향 자체가 변경**됩니다.

중력이 아래뿐 아니라 위, 좌, 우, 앞, 뒤로 전환되며,
이에 따라 어떤 주사위 면이 현재의 유효한 값인지 판단하는 기준도 함께 바뀝니다.

플레이어는 다음 요소를 함께 고려하여 `GRAVITY`를 완성해야 합니다.

- 주사위 면의 배치
- 변경된 중력 방향
- 카메라 시점
- 공간 방향

---

### Stage 5 — Sound / Melody

주사위 면에 직접적인 시각 정보가 존재하지 않는 청각 기반 퍼즐입니다.

방 안의 별 조명이 일정 시간마다 순차적으로 변화하며,
현재 활성화된 별에 따라 주사위가 구를 때 발생하는 충돌음의 음높이가 변경됩니다.

각 음높이는 `도–시` 음계 중 하나에 대응하며,
이 음계가 현재 주사위의 값처럼 사용됩니다.

플레이어는 슬롯의 높이 배치를 단서로
**반짝반짝 작은 별**의 멜로디를 연주하여 정답을 입력합니다.

---

### Stage 6 — LASER

주사위에는 `L / A / S / E / R`와 경고 문양이 배치되어 있습니다.

스테이지 내부에는 위험 구역이 존재하며,

- 주사위가 위험 구역에 진입하거나
- 경고 문양이 있는 면이 활성화되면

주사위를 향해 레이저가 발사됩니다.

레이저가 작동하면 기존에 슬롯에 입력해 두었던 값들이 모두 초기화됩니다.

따라서 플레이어는 주사위 면의 배치를 기억하면서
위험 구역을 피하고 `LASER` 순서를 완성해야 합니다.

---

### Stage 8 Navigation

주사위에는 다음 여섯 방향이 표시되어 있습니다.

`U / D / R / L / F / B`

- Up
- Down
- Right
- Left
- Front
- Back

플레이어는 3D 미로를 탐색하고,
미로에서 탈출하기 위해 사용한 이동 방향을 기억해야 합니다.

미로를 빠져나온 뒤 해당 이동 순서를 슬롯에 입력하면 스테이지가 완료됩니다.

즉, **미로를 통과한 이동 기록 자체가 퍼즐의 정답**이 됩니다.

---

### Stage 9 — SHADOW

방 전체가 어둡고, 방의 여섯 방향에 다음 문자가 배치되어 있습니다.

`S / H / A / D / O / W`

주사위 자체에는 아무런 문자나 문양도 표시되지 않습니다.

주사위를 굴릴 때마다 특정 방향의 광원이 활성화되며,
플레이어는 주사위가 만드는 **그림자의 방향**을 통해 현재 주사위의 값을 간접적으로 추론해야 합니다.

이를 반복하여 `SHADOW`를 입력하면 퍼즐을 완료할 수 있습니다.

# 주요 기술 구현

## 1. 공통 주사위–슬롯–정답 처리 구조

각 스테이지는 서로 다른 퍼즐 기믹을 사용하지만,
기본적인 조작과 판정 과정은 하나의 공통 구조를 공유합니다.

```text
플레이어 입력
    ↓
주사위 물리 처리
    ↓
중력 기준 면 판정
    ↓
현재 주사위 값 결정
    ↓
슬롯 입력 / 회전
    ↓
정답 비교
    ↓
시각적 피드백 / 스테이지 완료
```

이를 통해 각 스테이지는 주사위의 **값을 해석하는 규칙만 변경**하면서
기본적인 입력 및 정답 판정 시스템을 재사용할 수 있도록 구성했습니다.

### 주요 구성 요소

- `MainManager`
  - 주요 Manager 참조 관리
  - `DiceManager`, `AnswerManager`, `CamManager` 연결

- `InputManager`
  - 마우스 입력 처리
  - `Raycast`를 이용한 주사위 및 슬롯 입력 분기

- `DiceManager`
  - 주사위 드래그 및 투척
  - `Rigidbody` 기반 힘과 회전력 적용
  - 현재 중력 방향에 따른 투척 방향 재계산

- `FaceManager`
  - 각 주사위 면의 접촉 상태 추적
  - `Physics.gravity`를 기준으로 현재 유효한 면 판정

- `SlotManager`
  - 현재 주사위 상태를 슬롯에 저장
  - 슬롯 내부 주사위 생성 및 방향 표시
  - 동일한 면 재입력 시 90° 회전
  - 슬롯 초기화

- `AnswerManager`
  - 각 슬롯의 값과 정답 비교
  - 여러 형태의 허용 가능한 정답 상태 지원
  - 정답 / 오답 LED 표시
  - 완료 효과 및 다음 장면 전환

---

## 2. 중력 기준 주사위 판정 시스템

일반적인 주사위 시스템에서는 월드 좌표의 `Vector3.up`을 기준으로 윗면을 판단할 수 있지만,
DICE CODE에서는 Stage 4에서 중력 방향 자체가 변경되기 때문에 고정된 축을 사용할 수 없습니다.

각 `FaceManager`는 현재의

```csharp
Physics.gravity.normalized
```

값을 기준으로 중력의 반대 방향에 위치한 면을 현재 주사위 값으로 판정합니다.

또한 주사위 면이 바닥이나 벽에 일정 시간 이상 접촉한 경우에만 값을 확정하도록 하여,
주사위가 굴러가는 도중 값이 불안정하게 변경되는 것을 방지했습니다.

`DiceManager` 역시 중력이

```text
Down
Up
Left
Right
Forward
Back
```

어느 방향으로 설정되어 있더라도 동일한 드래그 조작으로 자연스럽게 주사위를 던질 수 있도록
힘과 회전력의 방향을 현재 중력 기준으로 변환합니다.

---

## 3. 슬롯 상태와 주사위 회전 처리

슬롯에는 단순히 `1–6`과 같은 값만 저장하지 않습니다.

주사위 면의 종류와 해당 면의 회전 방향을 함께 표현할 수 있도록
여러 방향 상태를 하나의 `slotValue`로 관리합니다.

이를 통해 다음과 같은 조작을 동일한 시스템 안에서 처리할 수 있습니다.

```text
6
↓ 90° 회전
9
```

슬롯 내부에 표시되는 주사위 역시 해당 상태에 맞는 `Quaternion` 회전을 적용하여
실제로 입력된 방향을 시각적으로 재현합니다.

---

## 4. 스테이지별 기믹 시스템

공통 퍼즐 구조 위에 스테이지별 구성 요소를 추가하여
같은 주사위가 서로 다른 정보를 표현하도록 확장했습니다.

### 색상 변환

`ColorDiceManager`

주사위의 결과를 재질과 조명의 색상에 연결하여
RGB/CMY 상태를 생성합니다.

```text
주사위 값
    ↓
색상 변환
    ↓
주사위 재질 + 환경 조명
```

### 동적 중력

`GravityBehave`

현재 주사위 값을 기준으로 `Physics.gravity`를 여섯 축 방향 중 하나로 변경합니다.

```text
주사위 면
    ↓
방향 판정
    ↓
Physics.gravity
    ↓
새로운 주사위 기준 방향
```

이로 인해 퍼즐의 상태가 단순한 화면상의 값이 아니라
Unity의 물리 환경 자체에 영향을 주도록 구성했습니다.

### 음계 주사위

`starBehave`  
`VertexManager`

별 조명을 일정한 시간 간격으로 순환시키고,
각 별의 상태를 특정 음높이와 연결합니다.

주사위 충돌이 발생하면 `Rigidbody`의 속도에 따라 충돌음의 크기를 조절하고,
현재 별의 상태에 따라 소리의 음높이를 변경합니다.

이를 통해 주사위 면의 시각 정보 대신
**소리의 음높이 자체를 주사위 값으로 사용하는 퍼즐**을 구현했습니다.

### 레이저 위험 요소

`laserTurretBehave`

레이저 장치는 주사위의 위치를 지속적으로 추적하며,
위험 상태 또는 특정 경고 면이 활성화되었을 때 레이저를 발사합니다.

레이저가 작동하면 다음 요소를 함께 처리합니다.

- `LineRenderer` 기반 레이저 표시
- 음향 효과
- 파티클 및 연기 효과
- 기존 슬롯 값 초기화

이를 통해 퍼즐 풀이 과정에 공간적 위험 요소와 실패 조건을 추가했습니다.

---

## 5. 카메라와 상호작용 피드백

`CamManager`를 통해 여러 고정 시점으로 카메라를 전환할 수 있도록 구성하여,
3차원 공간의 방향 자체가 퍼즐의 단서로 활용될 수 있도록 했습니다.

또한 다음과 같은 피드백을 퍼즐 상태와 연동했습니다.

- 드래그 방향 UI
- 슬롯 LED 상태
- 음향 효과
- 파티클 효과
- 스테이지 완료 시 카메라 전환
- 튜토리얼 텍스트 진행

퍼즐의 규칙을 별도의 설명문으로 직접 알려주기보다,
플레이어가 환경과 시스템의 반응을 관찰하여 규칙을 스스로 추론하도록 설계했습니다.

# 기타 구현 시스템

## 조작 방법

| 입력 | 동작 |
|---|---|
| 마우스 왼쪽 드래그 | 주사위 투척 방향 설정 |
| 슬롯에서 마우스 왼쪽 클릭 | 현재 주사위 값 입력 |
| 이미 입력된 슬롯에서 왼쪽 클릭 | 가능한 경우 주사위 회전 |
| 슬롯에서 마우스 오른쪽 클릭 | 슬롯 초기화 |
| W / A / S / D | 시점 변경 |
| Esc | 기존 시점으로 복귀 |

일부 조작은 스테이지에 따라 다르게 동작할 수 있습니다.

# 시스템 구조

```text
                    ┌─────────────┐
                    │ InputManager│
                    └──────┬──────┘
                           │
             ┌─────────────┴─────────────┐
             ▼                           ▼
      ┌─────────────┐             ┌─────────────┐
      │ DiceManager │             │ SlotManager │
      └──────┬──────┘             └──────┬──────┘
             │                           │
             ▼                           │
      ┌─────────────┐                    │
      │ FaceManager │                    │
      └──────┬──────┘                    │
             │                           │
             └─────────────┬─────────────┘
                           ▼
                    ┌───────────────┐
                    │ AnswerManager │
                    └───────┬───────┘
                            │
                      정답 / 오답
                            │
              ┌─────────────┴─────────────┐
              ▼                           ▼
          피드백                      다음 스테이지
```

스테이지별 구성 요소는 동일한 주사위 상태를 서로 다른 방식으로 해석합니다.

```text
ColorDiceManager ──► 색상
GravityBehave    ──► 중력
starBehave       ──► 음높이 / 조명
VertexManager    ──► 충돌음
Laser System     ──► 위험 상태 / 초기화
```

# 게임 설계 방향

DICE CODE의 핵심 설계 원칙은 다음과 같습니다.

> **조작 방식은 유지하고, 그 조작이 의미하는 규칙을 바꾼다.**

각 퍼즐마다 완전히 새로운 조작법을 추가하는 대신,
게임 전반에서 하나의 육면체 주사위와 동일한 슬롯 입력 방식을 반복해서 사용합니다.

대신 주사위를 해석하는 기준이 스테이지마다 변화합니다.

```text
주사위 면
→ 숫자
→ 회전
→ 색상
→ 중력
→ 소리
→ 공간적 위험
→ 이동 경로
→ 그림자
```

이를 통해 플레이어가 기본 조작법을 반복해서 새로 학습하지 않아도,
각 스테이지에서는 새로운 방식의 추론과 문제 해결을 경험하도록 설계했습니다.
